# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An Apple Macintosh Plus core (68000 8 MHz, 128 KB ROM, RAM up to 4 MB, 512 x 342 x 1 screen, IWM + two 800 KB floppies, SCSI, VIA, SCC, RTC / PRAM) for the Karabas Go, Mini and Mini G boards (Xilinx Spartan-6 XC6SLX25, ISE 14.7, XST): a port of [NanoMac](https://github.com/MiSTle-Dev/NanoMac) (Till Harbaum, Tang Nano 20K, commit 7af8fbd), donors [MacPlus_MiSTer](https://github.com/MiSTer-devel/MacPlus_MiSTer) (47c7ecf: SE / 512Ke / 128K models, HD20, floppy format) and [plus_too](https://github.com/mist-devel/plus_too) of MiST.

Status (2026-11-11): phase 0 done (machine alone 7902 LUT = 52 %, 13 RAMB16, 70 MHz), next phase 1 (Verilator sim). Docs, in Russian: `docs/PLAN.md` (research, decisions, phases). Follow the phases; record a changed decision in PLAN.md. One branch + one PR per phase, merged at the end of the phase.

User decisions (2026-11-11): name `macplus` (`macplus.kg`, `/macplus`), public repo; **RAM 4 MB in SDRAM, ROM 128 KB in SRAM** (firmware loader, `FL`), as in core-atarist; **video through a BRAM frame buffer** 512 x 342 x 1 (11 RAMB16), output **1024 x 768 @ 60 Hz (65 MHz), every pixel 2 x 2** (1024 x 684 centred). The Mac ROM and System are user files (Apple): never in the repo or the `.kg`. All file work goes through the firmware (OSD, `FL` / `F` items, `img_sdc`): no loader or soft CPU in the core.

Test files (local only): `~/Downloads/karabas-sd-macplus/macplus/plus.rom` (Plus v3, checksum 4D1F8172) and `Disk605.dsk` (System 6.0.5, raw 819200); `src/` there: `boot1.rom` (SE), `boot2.rom` (64 KB: 128K / 512K), `empty_hdd.zip` (`boot.vhd` 20 MB).

Templates: `../karabas-go-core-atarist` (the same MiSTeryNano family: fx68k through sv2v, `hid.v` + keymap, `img_sdc` for the `sdc_*` sector interface, SDRAM RAM + SRAM ROM, Makefile, Verilator harness), `../karabas-go-core-archie` (recent layout, sim scripts with `JOB-STAGE:` lines).

## Layout

- `docs/PLAN.md`: the plan.
- `src/make_core.py`: a symlink to `../../karabas-go-tools/make_core/make_core.py`.
- `modules/`: the git submodule [karabas-go-modules](https://github.com/andykarpov/karabas-go-modules). Clone with `--recursive`. A change to a module is made there (branch + PR) and taken here by moving the submodule commit.
- `src/rtl/macplus/` (NanoMac rtl), `src/rtl/fx68k/`, `src/rtl/companion/` (`hid.v`, keymap): changes marked `// karabas:`. `src/rtl/tang/`: the Tang top, SDRAM and SD model, reference only.
- `src/rtl/sv2v/` + `src/macplus.prj`: generated by `src/tools/sv2v.sh` (in git; rerun after a source change).
- `src/Makefile` (as core-atarist: `make minig`, `make macplus-xst` / `macplus-report` = the machine alone), `src/core.json` (draft until phase 2), `src/sim/` (NanoMac Verilator harness, paths to fix in phase 1).

## Rules of the core

The rules of core-atarist apply: standard video timing with syncs always present (the user's monitor rejects anything else), `FT_CLK_OUT` about 8 MHz on Mini / Mini G, Go `FDC_*` outputs 0 when unused, OSD switch index = item position unless `"index"`, an OSD value shows 10 characters at most, FL slots 0..7 only (one array with the F slots), Verilog-2001 for XST (`sv2v` for SV), imported code marked `// karabas:`.

- Mini / Mini G tops drive T3 (`FLASH_CS_N`) = 0: on Mini G2 it is the SDRAM ~CS.
- Registers with no reset that leave their idle state only through a condition on themselves get trimmed by XST (works in sim, not on the board): give them an initial value and read the `.syr` for Xst:1710 / 2404.
- Builds: map / PAR with cost table 2 first; no needless all-board PAR runs. Long sims (minutes) only after asking the user; start them with `job run` + Monitor on `job watch`.
- Board checks through the shared bench queue (`hwq`), ask before flashing.
